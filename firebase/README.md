# Firebase共有シフト・打刻・月別集計

管理者: omotesandodc@gmail.com（Googleログイン・メール確認済みが必要）。
管理者が6人の名前とGoogleメールを登録し、スタッフはシフトを閲覧します。
編集権限はFirestoreルールでも管理者に限定しています。
元のブラウザ内シフトは自動移行しません。既存データは旧画面からバックアップしてください。

## 公開

Node.jsとFirebase CLIを導入後、このfirebaseフォルダで実行します。

```sh
firebase login
firebase deploy --only firestore:rules,hosting --project odc-attendance-60c43
```

firebase init は不要です。設定ファイルを用意しています。
公開先: https://odc-attendance-60c43.web.app

## 出勤・退勤

スタッフ設定に登録されたGoogleメールの本人が打刻します。管理者も打刻する場合は、6人のいずれかに管理者メールを登録してください。
日本時間で1日1回の出勤・退勤です。Firebaseのサーバー時刻を保存し、端末の日付が不正な場合は保存を拒否します。
本人の現在の打刻と日別履歴をトランザクションで同時保存します。ルールでも同時保存・本人限定・過去の出勤時刻の変更禁止・二重打刻禁止を強制します。
前日以前の出勤が未退勤なら、新たな出勤はできません。日をまたいで退勤できますが、打刻忘れは管理者に時刻修正を依頼してください。
オフラインでの打刻はできません。保存完了表示と履歴を確認してください。
自分の履歴は直近31件を表示します（読み込みは本人の全履歴）。院内Wi-Fi制限は未実装です。

## 管理者の一覧と月別集計

管理者ログイン時だけ「管理者用・打刻一覧と月別集計」を表示します。対象月を選んで「一覧を表示」で最新データをサーバーから取得します。読み込み失敗時は部分的な一覧やCSVを出しません。
打刻がある人だけを表示し、日本時間の出勤日で対象月を判定します。日をまたぐ勤務は全時間を出勤月に計上します。打刻日数は勤務予定や欠勤日数ではありません。
管理者が月別一覧を開くと、退勤済みかつ勤務60分以上で休憩未入力の日に60分を自動保存・控除します。過去の未入力日も対象です。自動入力は「自動（60分）」と表示し、実働合計に含めます。違う日だけ管理者が実際の休憩を整数の分数で修正してください。勤務60分未満は自動入力せず、手入力を待ちます。既存の休憩（0分を含む）はトランザクションで保護し上書きしません。シフト設定の休憩とは連動せず、自動値は60分固定です。休憩未確認・退勤未打刻の日は実働合計から除外し、未確認日数を表示します。
秒単位の記録から計算し、画面とCSVは時:分で表示します。表示の秒は切り捨て、月別合計は元の精度で合算してから表示します。残業・有給・給与の計算は含みません。
明細と月別集計のCSVをそれぞれ出力できます。既存のシフトCSVとバックアップはシフト専用のままです。

本人が更新後の画面でログインすると、認証メールとスタッフ設定からstaffProfiles/{uid}へ氏名を連携します。既存の打刻は保持し、名前未連携の場合もUID付きで表示します。管理者は本人の再ログイン後に一覧を再表示してください。登録外となったアカウントの過去の打刻も表示します。
休憩はattendance/{uid}/reviews/{day}へ保存し、元の打刻時刻は変更しません。保存者・サーバー保存時刻・自動／手入力の区別を記録します。休憩変更の全履歴は残しません。別画面からの休憩更新は競合を検出して再読込を求めます。

## 検証

共有シフトは管理者の保存・再読み込み・別端末表示、スタッフの閲覧と編集ボタン無効を利用者確認済みです。
打刻はJavaScript構文・HTML要素参照とFirestoreエミュレータで検証。出勤・再読み込み後の保存・退勤・履歴表示は利用者の実機で確認済みです。
ルール検証は本人の読み書き、他人・未登録・未ログインの拒否、管理者による代理打刻の拒否、偽の時刻・日付の拒否、履歴との同時保存、同時二重打刻、時刻改変・削除の拒否、日またぎ退勤を対象にしています。

## 管理者の打刻修正

月別一覧の「時刻修正」から日本時間の出勤・退勤日時と理由を保存します。「打刻忘れを追加」は登録済みプロフィールから対象者を選び、その月の記録を作成します。スタッフ本人の初回ログインが必要です。出勤日の移動・記録削除には対応しません。勤務中は退勤を空欄にできますが、新しい日の打刻がある場合は過去の日を未退勤にはできません。未来時刻や逆転した時刻は拒否します。

日別記録と必要に応じ現在の打刻状態を同時更新します。attendance/{uid}/corrections/{id}に変更前後・理由・管理者UID・サーバー保存時刻を同時保存し、履歴の更新・削除は禁止します。元データはこの履歴で保持します。別画面や本人の打刻と競合したら再表示を求めます。時刻修正後は休憩を維持し、勤務時間を超える休憩は未確認として合計から除外します。本人の履歴にも修正後時刻が反映されます。

## 本人による打刻修正申請

登録スタッフは自分の記録だけを追加・修正申請できます。自分の月別一覧から操作し、理由は必須です。Firestoreルールで本人のUIDと登録メールを確認し、他人の記録・履歴へのアクセス、修正者の偽装、履歴の上書き・削除を拒否します。管理者は引き続き全員の記録を修正できます。

一覧と明細CSVの状態に「本人修正あり」「管理者修正あり」を表示します。後から管理者が再修正しても本人修正の印は残します。「修正履歴」で変更前後・理由・本人／管理者・日時を確認できます。本人の申請はcorrectionRequestsへ承認待ちとして保存され、管理者承認まで正式な記録・実働集計には反映しません。管理者画面は全月の承認待ち申請を一覧表示し、変更前後・本人・理由・申請日時を確認して「承認」「却下」をワンクリックで選べます。承認は申請状態・正式記録・修正履歴をトランザクションで同時保存します。却下時は正式な記録を変更しません。本人は自分の申請の承認待ち／承認済み／却下を確認できます。二重処理と、申請後に正式記録が変わった場合の上書きを拒否します。旧版ですでに正式保存した修正はそのまま維持します。休憩の変更・自動入力は管理者専用です。

## 有給の申請・残日数

登録スタッフは1日単位のみで申請できます。管理者が残日数を後から整数の日数で設定します。未設定でも申請でき、未設定・不足時は承認を止めます。スタッフが初回ログインすると残日数設定の対象に表示します。管理者の残日数再設定には理由が必要で、設定前後・理由・保存者・日時を履歴に残します。残日数は承認済みの未来の取得予定も差し引いた申請可能日数です。初期設定はこれから承認する申請の取得分を差し引く前、再設定は承認済み予定を差し引いた現在残数を入力します。

leaveRequestsに申請と承認／却下／承認取消を保存します。承認時にleaveBalancesの残日数とleaveDaysのシフト表示を同時更新します。既存データとの互換性のため内部保存は1日＝2単位を維持します。半日の新規申請と承認は画面・サーバーの両方で禁止します。既存の半日履歴は保持し、却下・取消は可能です。残日数不足・同日の同じ時間帯の二重承認を拒否します。却下は残日数を変えません。管理者が承認取消すると残日数を返し、シフトの有給表示を解除します。残日数の古い画面からの保存も拒否します。

承認済み有給をシフト画面とシフトCSVに反映します。既存シフトを上書きせず、その上に全日「有」・半日「午前有／午後有」を表示します。シフトセルから直接選ぶ旧「有給」は予定表示のみで残数に反映しません。申請備考・残数は本人と管理者だけが読み取れ、シフト用の取得区分は登録メンバーに共有します。付与・失効の自動処理、取得年度別集計、給与計算は含みません。

検証: `node tests/leave-rules.mjs` をFirestoreエミュレータで実行。未設定申請・残数設定権限・承認時の同時更新・半日・重複・却下・取消返却・残不足・残数編集競合・管理者UIを確認します。
